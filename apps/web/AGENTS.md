# Web 開発ルール
- ルートの `AGENTS.md` を守る。
- ブラウザ向け表示・ロジック・新規テストを TypeScript（`.ts`、JSX が必要な場合のみ `.tsx`）に統一する。既存テストも含めて `.ts` に統一し、手書き `.mjs` / `.js` は追加しない。新規テストは `tsconfig.test.json` と `pnpm --filter @discord-mock/web test` で検証する。Mock の真の状態は Server が管理する。
- ダミーユーザーと管理者の権限は区別する。DM と権限をブラウザだけで保護しない。
- 外部サービス・Discord 本番のトークンにアクセスしない。
- テスト画面はローカルの TypeScript UI。ダミーユーザー切り替え・投稿はセッション Cookie + CSRF トークンで保護し、発火した MESSAGE_CREATE は Mock Gateway 経由で Bot に渡す。Bot の REST 投稿は SSE でブラウザへ反映する。管理画面の CRUD、DM、VC 音声はまだ未実装。

- `/test` は自動テスト画面。左サイドバーにテキストチャンネル一覧、中央のチャットにダミーユーザーの操作と Bot の応答（Embed 等）、独立した右側の実行ログにテスト開始・ステップ・成功／失敗を表示する。実行ボタンは下部のコンポーザーに配置する。従来のダーク配色を維持し、テスト状態と通常データを混ぜない。`/tests` の履歴は維持する。

- `/test` のダミーユーザー選択欄は表示する。UT の `"login"` はこの選択値（`/_ui/session` のセッション側）に連動する。テストボタンは `/_ui/test-cases/run` にユーザーのCSRFで送信し、任意のユーザーIDをリクエストで渡さない。結果閲覧用の管理セッションとは区別する。

- /test の右サイドバーは実行ログとユーザー一覧をタブで切替。ユーザー左クリックはロール付きプロフィール、右クリックはログイン変更とIDコピーのコンテキストメニュー。既定ユーザーは10人。ブラウザセッション認証とCSRFを維持する。

- `/test` は画面高を固定しチャットのみ縦スクロール、メッセージ増加時は最新に追従。下部テストボタンや左右サイドバーを押し出さない。
- `/database` はApp DBと、テスト実行後の読み取り専用PGliteスナップショットを切り替える。テストの表示データをAppの実DBへ混入させない。

- `/test` のプロフィールと右クリックメニューは外側のpointerdownとEscで閉じる。左サイドバーの「＋」から `/_ui/channels` （ブラウザセッション・CSRF検証）でテキストチャンネルを作成し、Appとテスト用Mockで共有できるチャンネル定義にする。
