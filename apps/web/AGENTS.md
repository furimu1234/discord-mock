# Web 開発ルール
- ルートの `AGENTS.md` を守る。
- ブラウザ向け表示・ロジック・新規テストを TypeScript（`.ts`、JSX が必要な場合のみ `.tsx`）に統一する。既存テストも含めて `.ts` に統一し、手書き `.mjs` / `.js` は追加しない。新規テストは `tsconfig.test.json` と `pnpm --filter @discord-mock/web test` で検証する。Mock の真の状態は Server が管理する。
- ダミーユーザーと管理者の権限は区別する。DM と権限をブラウザだけで保護しない。
- 外部サービス・Discord 本番のトークンにアクセスしない。
- メッセージURLは現在のApp内に発行し、テスト結果では実行ID・チャンネルID・メッセージIDを含める。右クリックはサーバーのcanEdit/canDeleteに従って編集・削除を表示し、リンクコピーは表示できるメッセージすべてで可能。削除は確認する。URLを開いても選択ユーザーを変更しない。実行ログから最初の閲覧可能なメッセージへ移動し、移動先の背景を3秒間だけ強調する。通常の再描画では残りの強調時間とスクロール位置を保ち、期限後の強調を復活させない。新しいテストの起動・進捗更新時はリンク閲覧を解除し、チャットと実行ログを同じ更新で末尾へ追従させる。編集フォームは再描画から分離して入力を保持する。
- テスト画面はローカルの TypeScript UI。ダミーユーザー切り替え・投稿はセッション Cookie + CSRF トークンで保護し、発火した MESSAGE_CREATE は Mock Gateway 経由で Bot に渡す。Bot の REST 投稿は SSE でブラウザへ反映する。管理画面の CRUD、DM、VC 音声はまだ未実装。

- `/test` は自動テスト画面。左サイドバーにテキストチャンネル一覧、中央のチャットにダミーユーザーの操作と Bot の応答（Embed 等）、独立した右側の実行ログにテスト開始・ステップ・成功／失敗を表示する。独自のテストケース選択リストは下部のコンポーザーに配置し、Enter／ダブルクリックで実行する。実行ボタンは設けない。従来のダーク配色を維持し、テスト状態と通常データを混ぜない。`/tests` の履歴は維持する。

- `/test` のダミーユーザー選択欄は表示する。UT の `"login"` はこの選択値（`/_ui/session` のセッション側）に連動する。選択したテストの実行は `/_ui/test-cases/run` にユーザーのCSRFで送信し、任意のユーザーIDをリクエストで渡さない。結果閲覧用の管理セッションとは区別する。

- /test の右サイドバーは実行ログとユーザー一覧をタブで切替。ユーザー左クリックはロール付きプロフィール、右クリックはログイン変更とIDコピーのコンテキストメニュー。既定ユーザーは10人。ブラウザセッション認証とCSRFを維持する。

- `/test` は画面高を固定し、チャットと実行ログを各領域内で縦スクロールする。テスト実行時は両方が同時に最新へ追従する。下部テストケース一覧や左右サイドバーを押し出さない。
- `/database` はApp DBと、テスト実行後の読み取り専用PGliteスナップショットを切り替える。テストの表示データをAppの実DBへ混入させない。

- `/test` のプロフィールと右クリックメニューは外側のpointerdownとEscで閉じる。左サイドバーの「＋」から `/_ui/channels` （ブラウザセッション・CSRF検証）でテキストチャンネルを作成し、Appとテスト用Mockで共有できるチャンネル定義にする。

- テストケース一覧は常時展開した独自の `listbox` とし、各行の左側に四角い枠を表示する。矢印キー／マウスカーソルで選んだ行の背景を強調する。Enter／ダブルクリックで実行した行の枠内に、その操作から3秒間だけ「●」を表示する。ケースなし・実行中は起動できず、Enterのキーリピートでも重複実行しない。固定高さで内部スクロールを維持し、スクロールバーは非表示にする。キーボードで選んだ行は表示範囲へ追従する。テスト名は `describe` の階層付きで表示する。ポーリング時は一覧に変更がない限りDOMを再構築せず、選択・スクロール位置・印の残り表示時間を保持する。既存のダーク配色を保ち、チャットとサイドバーは別領域で表示する。
